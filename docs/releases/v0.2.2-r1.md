## 1. 为什么会有这一版

本机 DSH 桌面版 `2.0.22-next` 的内核已经是 `0.2.2-rc.1`（2026-11-05 安装），
但桥接的 `src/dsh-client.js` 还停在 0.2.1 的语义。DSH 0.2.1-rc.3 起改了一件与桥接**直接相关**的事：

> `session/follow` 默认不再激活冷会话 —— 只读历史、不 promote Agent。

桥接的 `sendOpen()` 只发了 `address` 和 `maxMessages`，**没有 `activate`**。后果是：
**DSH 重启后，带 pending inbox 的冷会话永远不跑**。QQ 侧的表现是「桥接连上了、网关也活着、
`qq_status` 是 online，但她就是不说话」—— 排查时最容易误判成网关或 QQ 的问题。

2026-11-08 晚就撞过一次：网关被杀后重启，桥接 22:41:19 重连成功、昵称都读到了，
但会话里的待办一直没有恢复执行。

## 2. 改了什么

### 2.1 `src/dsh-client.js` —— 显式激活冷会话

```js
request: {
  address: { kind: 'session', sessionId },
  activate: true,          // ← 本版新增
  maxMessages: FOLLOW_SNAPSHOT_MESSAGES
}
```

对齐上游 `v0.2.2-rc1` 的 `src/dsh-client.js:759`。
这不是"抄一行"，而是恢复 0.2.1-rc.3 **之前**的语义：桥接启动/重连后要能接着跑没跑完的回合。

### 2.2 `scripts/verify-dsh-021-adaptation.mjs` —— 插件版本断言放宽

原来的断言是「qq-mode-console 插件版本必须等于主包版本」。这条在**两个包本来就走不同版本线**时
是错的：`plugins/qq-mode-console` 与 `plugins/qq-agent-presets` 是独立分发的 DSH 插件包
（npm 上到 `1.1.2`，且通过 Junction 链接进 `~/.dsh/plugins/`），并非桥接的一部分。

改成只要求它是**合法 semver**（`/^\d+\.\d+\.\d+/`），保留"防止漏写成空串"的原意，
不再把"插件版本号与主包不同"判成失败。

## 5. 遗留问题：注册期守卫仍在空转

`~/.dsh/logs/desktop-next.log` 里 `[qq-tool-restrict] skip restrict <name>: tools.restrict() names unknown global tool`
共 **190 行**。原因是 DSH **全局层只有 9 个工具**（3 个 MCP resource + `video_*` + `working_directory`），
`restrict()` 对不在全局层的名字直接抛错、被 try/catch 吞掉。

**安全上没有漏洞**：执行期 `ctx.tools.guard` 的 `verdictFor()` 实测对 `schedule_create/edit/view/list`
在 owner-private / group / member-private 三种身份下**全部 DENY**，那道才是真正的边界。
注册期这一层是回归网，等哪天有别的 composition 把这些名字挂进全局层时才会起作用。
