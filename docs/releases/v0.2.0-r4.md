## 一、她自己的时间：主动、自由时间、约定

这一批解决的是同一个问题：**她原来只在被叫到时才存在**。现在她有自己的钟、自己的判断，
以及一套「哪些事她能自己决定、哪些必须当场问」的边界。

### 1. 时间感（`src/time-context.js`，217 行）

把「现在几点、星期几、什么时段、是不是饭点、离上次说话多久」算成一句她读得懂的话，
交给提示词。纯函数、不碰文件、不碰网络。

- 时段划分（深夜 / 凌晨 / 清晨 / 上午 / 中午 / 下午 / 傍晚 / 晚上 / 深夜）**用同一套边界**，
  既给提示词用，也给「这个点该不该主动找他」的系数用 —— 以前是两处各写一份，改一处就漂移。
- 「该不该自然提一句」只作为建议输出，**不替她决定说什么**。
- 钉住它的测试：`scripts/test-proactive-time.mjs`（时段/饭点边界、`parsePermitAnswer` 的否定词、
  `permit-lib` 的 fail-closed）。

### 2. 自由时间：聊完之后那一小段（`quietGrantMs()`）

主人原话：「感觉小鲸鱼自主的时间太少了，希望她现在判断结束对话后的短暂时间也算她的自由时间」。

- 她判断这段对话结束后，静默达到阈值（默认 **150 秒 / 2.5 分钟**）即视为进入**自主回合**，此时空间写操作放行。
- 阈值钳制在 **[10 秒, 60 分钟]**：下限防止设成 0（那等于闸门形同拆除），上限防止「短暂」变成常态。
- 有三条必须成立才盖章，缺一不算：**①** 原有自主唤醒判据一条没松（`AUTONOMOUS_WAKE_REASONS`
  仍是 `proactiveCheck` / `timeout` / `replyCheck` 三个）；**②** 盖章用「现在」当 `turnStartedAt`
  （否则会被 15 分钟 TTL 当场判过期）；**③** 期间收到新消息或拍一拍会**取消**待办
  （不然变成「边聊边发说说」）。静默回合不盖章。
- 钉住它的测试：`scripts/test-quiet-autonomy.mjs`。

### 3. 「静默只是允许，不是必须」（`qzoneWriteMinGapMs`）

主人原话：「自由时间不是一定要发说说，我不希望每个对话结束她都去发说说」。

静默盖章会让**每次聊完**都产生一次空间写权限，而拿到权限她就会去用 —— 结果是每聊完一次，
空间里就多一条说说。提示词里只说「只能是你真想说的」**管不住频率**，所以在执行期再加一道：

- 同一会话**两次空间写操作之间**至少隔 `socialV2.autonomy.qzoneWriteMinGapMs`（默认 **4 小时**，
  范围 `[0, 7 天]`，设 0 = 不限制）。
- 只限制**写**，不限制**读**（看空间、翻说说列表照旧随便）。
- 时间戳存在**会话状态里**（`st.qzoneWriteAt`），**重启不清零** —— 只在内存里记的话，
  桥接重启一次她就又有一次机会，等于绕过了约束。

### 4. QQ 空间的「只能她自己起头」闸门

空间的**写操作**（发说说 / 点赞 / 评论 / 删除 / 改可见性）只能发生在
`st.turnAutonomous === true` 的回合里 —— 任何人在对话里命令她去做都不成立，**包括管理员**。
实现点在执行期：`/api/socialV2/qzone-action` 与 `/api/socialV2/send-qzone` 都查这个标志，
标志由 `sendWakePromptV2` 按唤醒原因置位（`isAutonomousWakeReason`）。
钉住它的测试：`scripts/test-qzone-autonomy.mjs`。

### 5. 约定：她答应过的事（`qq_promise` / `qq_promise_done`）

「我明早叫你」「一小时后回来找你」这类话说出口就必须记下来，否则她睡一觉就忘了。

- 落盘在 `state/extra-promises.json`，到点由桥接**主动叫醒她**（不是发一条固定的话，
  而是把她叫起来、让她自己决定怎么说）。
- `kind` 三种：`wakeup`（叫起床）/ `remind`（提醒某事）/ `checkin`（回来找他）。
- `prunePromises` 清理过期条目；`formatPromisesV2` 把它排成人话塞进提示词。

## 二、「向我申请」硬闸门：玩手机 / 刷B站

这是本次**安全相关改动里分量最重的一块**。原来的问题是：手机工具（截图/点按/消消乐）和
`bili_run` 是**无条件**对她开放的，她随时可以动真实设备、花真实 token。

### 现在怎么做

- **桥接侧**（`src/permit-lib.js`，183 行）：负责「把授权写进 `state/permits.json`」和
  「算清楚给多久」。**它不是执行点** —— 就算它写错，最多是给多/给少时间，
  不可能让没被同意的人拿到工具。
- **守卫侧**（`plugins/qq-agent-presets/qq-tool-restrict.mjs`）：**唯一的执行点**。
  它读同一份 `permits.json`，自己判断「这个会话此刻有没有有效授权」。
- 为什么必须落文件、不能用内存 `Set`：守卫跑在 **DSH 进程**里（preset 的插件行），
  与桥接是两个进程，内存授权它看不见。落文件 + 守卫侧 2 秒短缓存是唯一能跨进程又不新增 RPC 的做法。

### 三类权能矩阵（`OWNER_PRIVATE_ONLY` / `BILI_OWNER_ONLY` / `PHONE_READONLY`）

守卫不再靠「会话 key 前缀」猜身份 —— 执行期它只看得到 `exec.agent.session.id`，拿不到 QQ 会话 key。
改成**按会话 id 反查 QQ 号**：桥接把 `private:<ownerQQ> → sessionId` 记在 `state/sessions.json`，
守卫读它。

> ⚠️ **fail-closed**：找不到仓库根 / 读不到文件 / 会话不在表里 / `ownerQQ` 没配
> ⇒ 一律当成「不是主人」，需要主人的工具（`BILI_OWNER_ONLY`）**全部拒绝**。
> 绝不因为「读不到」就放宽 —— 那正是最容易写出越权的一条路。

- `phone` scope：默认 30 分钟，上限 2 小时。
- `bili` scope：默认 60 分钟，上限 3 小时。
- 拒绝优先：`bili_config` / `bili_login` 即使在申请有效期内**仍然被拒**（它们改的是凭据，不是「玩」）。
- 手机**只读**工具（截图等不产生任何动作的）不需要申请。

钉住它的测试：`scripts/test-permit-gate.mjs`（含「群聊/普通成员写了授权也拿不到」、
「owner 私聊但没申请 → 拒绝 + 给出申请指引」、「坏文件当作没有授权」）。

## 三、专项控制台（`tools/extra-console/`，端口 3101）

主人原话：「针对这些独特的功能单独做一个补充控制台吧，方便我自己操作的，不用每次找你的
选择性的功能，我害怕如果加上到现有的控制台上，万一插件更新了，我的修改就没了。」

所以它刻意遵守三条硬约束，且**每一条都有测试钉住**（`scripts/test-extra-console.mjs`）：

1. **不复用 `public/console.html` 的任何一行** —— 那个文件被 git 跟踪，插件更新时整体替换。
   这里自带前端（`tools/extra-console/index.html`，66 KB），改它碰不到主控制台。
2. **不依赖桥接新增的任何路由** —— 只调 8 个在本次改动**之前就存在**的端点
   （`/api/socialV2/config`、`/states`、`/state`、`/wake`、`/api/test-send` 等）。
   就算 `bridge.js` 被整个换成上游新版、这次加的端点全丢，本控制台的「主动找人」「现场调试」两栏仍然可用。
3. **新增能力自己落盘** —— 授权（`permits.json`）与约定（`promises.json`）由本进程直接读写 `state/`，
   而 `state/` 在 `.gitignore` 里，**永远不会**被更新碰。守卫读的就是同一个 `permits.json`，
   所以「从这里批准」和「她在 QQ 里申请、你回同意」效果完全一致，都不经过桥接。

界面：左侧多页导航（**7 页**：主动找人 / 语音 / 自由时间 / 工具开关 / 申请闸门 / 约好的事 / 现场调试，
与按钮一一对应，背景/字体仿 3100 主控制台），44 个元素 id 齐全。

- **令牌不用手填**：桥接把 `state/console-token` 运行时注入页面（`injectConsoleToken`），
  不落静态文件、不进 git，定长比较。
- **语音常驻**：可以在面板里热切换语音开关（接口 + 桥接热读 + `tts.isEnabled()`）。
- **工具开关**：顶部横向标签按分组切换，角标跟着刷新；「操作开关」与「名字写错」会区分提示；
  多工具标注支持；**顺带修掉了群图库 4 个开关存不进去的老 bug**。
- **约定用原生日历控件**：本地时区解析、有默认值、拦过去时间。
- **自由时间的两个数字**（静默阈值、空间写最小间隔）能在面板里改，前后端钳制一致，标出默认值。
- 启动：根目录 `专项控制台.bat`，或 `npm run extra-console`；`launch-all.ps1` 会探活并在没起时拉起。

## 四、群图库与她的图库：两件不同的事

### 1. 群图库（`src/media-lib.js`，700 行，零外部包依赖）

原来的表情包体系只认 **QQ 账号的收藏表情**（`fetch_custom_face_detail`），
而群里真正好玩的是「群友随手发的图」—— 那些图在 QQ 侧没有 `emoji_id`、URL 还带一次性签名。于是：

- 拿 **md5** 当唯一键不行：同一张图被 QQ 重压缩/改尺寸/转格式后 md5 就变了，会重复收藏；
- 拿 **URL** 当唯一键更不行：`rkey` 每次都换。

改用两把真正管用的钥匙，**三重去重并联**、不靠单点：

| 钥匙 | 作用 | 盲区 |
| --- | --- | --- |
| `fileid` | QQ 多媒体 URL 里 `fileid=` 同一张图恒定不变 | 部分表情包没有 fileid |
| **dHash**（缩成 9×8 灰度、逐行比相邻像素明暗 → 64 位指纹） | 看画面结构而非字节，重压缩/改尺寸/转格式过的同一张图也认得出（汉明距离 ≤5） | 低对比度/纯渐变图会让「左>右」恒成立 → 指纹全 1 |
| `sha1` | 逐字节兜底 | 字节一变就失效 |

其他设计边界：下载一律走调用方传进来的字节（模块**不自己发网络请求**，SSRF/DNS 校验口径不变）；
`sharp` 是**可选**依赖，没有就退化成 sha1 逐字节判重，不报错不崩；
所有自由文本（desc/tags/msgText）复用 `sanitizeStickerText` 单行化 —— 这些字段会被注入提示词，
必须防住跨会话的提示词注入。

分层：`candidate` → `library` → `negative` → `trash`（候选 400 张上限、20 张/分钟、200 张/小时）；
`/api/photos/*` 六个端点（列表/统计/备注/晋级/回收/清理）。

### 2. 她的图库（`src/gallery-lib.js`，194 行）

与「收藏表情」是**两件不同的事**，别混：

- 收藏表情 = 可复用的**工具**，有 md5/id，能发出去，本质是「素材库」；
- 图库 = 不可复用的**纪念**，只有图 + 一句话，本质是「相册」。

约束：**只增不改**（不提供删除/改写）；**存字节不存 URL**（QQ/微信图片 URL 带签名，
存 URL 的「图库」三个月后全是死链）；**理由必填**（没有理由的收藏不叫「她挑的」，叫「下载」）。
工具：`qq_gallery_add` / `qq_gallery_list`。

## 五、语音：常驻语音（语音优先）

主人 2026-10-20 定下：他发文字、他发语音、群里跟他说话，她都回语音，除非语音用不了。

- `qq_speak` **合并进 `qq_say`**，`qq_say` 成为默认说话方式（`mode: voice-first`，
  发不出去自动改文字；`voice-only` 则失败即报错、绝不改文字）。
- 返回里的 `mode` 字段是**唯一可信的实况**：`voice` = 真发了语音条，`text` = 退成文字并给了原因。
  看到 `mode: "text"` **不要**重发 —— 桥接已经兜底发出去了。
- 三条必须打字的例外：需要精确阅读（链接/代码/长列表/数字）、群里要引用或 @、语音已连试两次失败。
- 修掉一个静默 bug：`createTts` 的 `cfg.enabled` 是**启动快照**，控制台关掉开关后它还是 `true`，
  于是「开关关了却还在发语音」。现在改成 `isEnabled()` 读注入的实时值，没注入时退回快照（单测行为不变）。

## 六、修掉的缺陷（每条都有回归测试）

### 1. 她把前一天的日记当成今天说（`src/diary-lib.js`）

**现象**：她对群友说「没刷视频，打了一下午消消乐」，而那天她**一次都没碰过游戏**
（当天 `phone_*` 调用数为 0，最后一次真玩是前一天）。

**根因不是她「编」，而是提示词没说清这是哪一天写的**：日记行原格式只有
`- 2026-10-18 19:04 下午摸进消消乐…`，正文里的「下午」不带日期，模型得自己把日期换算成
「这是昨天」才不会讲错 —— 它没换算，而提示词里**同时**给了「当前时间」，两行一凑就成了
「今天下午我在打消消乐」。

**修复**：行首显式标出 `【今天】` / `【昨天】` / `【10-18】`，日期归属不再依赖模型做减法；
摘要末尾写死「不能把以前某天的日记当成今天说」。`diaryDayLabel` 导出以便单测直接钉住滚动语义
（若测试自己重写一份算法，那份副本会随生产代码改动而失真，等于测了个假实现）。
「昨天」从**传入的 `today`** 反推，不另读时钟 —— 否则跨午夜时两次读钟可能落在两天，给出互相矛盾的标签；
用 12:00 做锚点减法，避开某些时区/夏令时切换日本地午夜不存在的问题。

### 2. 日记目录可配置（`socialV2.diary.dir`）

日记原本写死在 `data/日记`，主人想直接打开看（「日记专门放一个地方吧，方便我去找」），
所以改成可配置。两个容易写错的地方一人一条回归：

- **相对路径必须按仓库根（ROOT）解析，不能按 `process.cwd()`** —— 桥接从哪启动都有可能；
- **没配 / 空串必须回到原来的默认目录** —— 老日记不能因为这次改动就「消失」。

另外 `~` 会展开成用户主目录（写 `~/Desktop/日记` 更顺手），绝对路径原样用，怪值（数字等）
当字符串处理、**绝不抛**。解析逻辑做成**纯函数** `resolveDiaryDir(cfg)`，可单测、不看时钟；
进程内实际值由 `main()` 在 `loadConfig()` 之后写一次，之后统一走 `diaryDir()`。
测试：`scripts/test-audit-diary-dir.mjs`（9 项）。

### 3. 人格卡里出现两块一模一样的记忆索引（`plugins/qq-memory-rollover/memory-index.mjs`）

**根因（已复现）**：角色卡是 **CRLF**，而插件拼块用的是 `\n`；注入用的是
`/\n\n<!--start-->[\s\S]*<!--end-->/`（**贪婪 + 非全局**）—— 第一次注入后文件尾部变成 LF，
第二次注入时 `\n\n<!--start-->` 前缀匹配不上已存在的块 ⇒ `re.test()` 为 false ⇒ 走「追加」分支
⇒ 块越堆越多（实测坏成了两块）。

**修复**：把拼块/清理/注入抽成**纯函数**（只进出字符串，不碰文件系统），由
`scripts/test-memory-index.mjs` 钉住三件事：已存在的块必须被**替换**而非追加（单块多块都收敛成一块）、
行尾不许混（CRLF 文件里不能冒出裸 LF）、**幂等**（同样内容写两次，第二次不改文件）。

顺带定了容量策略：窗口 **7 天**、上限 **30 条**、每条的提示关键词上限 6 个。超限不是删除，是
滚出窗口（原文仍在日记里）。

### 4. 「反馈给主人」其实谁也没收到（`notifyOwnerOnError`）

`qq_report_feedback` 只把内容写进 `state/feedback.json`（控制台能看），而
`/api/socialV2/feedback` 里那段 `notifyOwnerOnError` 是**占位实现** —— 名字叫「通知 owner」，
实际只 log 一句，根本没发消息。⇒ 她「反馈了」，但没有任何人收到。

**修复**：换成真发私信。默认口径：`warning`/`error` 推、`info` 只记录；支持 `notify` 覆盖。
工具描述也改成「会真的发私信」（否则她以为只是写日志，不会用），提示词里补上
「发现出问题要告诉他」这一条。测试：`scripts/test-feedback-notify.mjs`。
