# v0.2.1-r1 更新日志（2026-10-26）

> **本版定性：只做版本更新。** 不加功能、不动人格文本、不改 `bridge.js` 业务逻辑。
> 改动全部落在 **安全守卫名单** + **两处方向写反的回归断言** + **版本身份**。
> 目标是让桥接对齐本机正在跑的 DSH `0.2.1-rc.2`，而不是把上游的新功能搬过来。

- 上一版：`v0.2.0-r5`（2026-10-24，DSH 0.2.0-rc.2）
- 本版：`v0.2.1-r1`（DSH 0.2.1-rc.2）
- 版本号方案：主版本与 DSH 同步，`rN` = 同一 DSH 版本下第 N 次发布（见
  [DSH_020_ADAPTATION 附录 H](../guides/DSH_020_ADAPTATION.md)）。

---

## 1. 为什么会有这一版

本机 DSH 已经升到 `0.2.1-rc.2`（`~/.dsh/logs` 的 `run.start` 里实测 `"dsh":"0.2.1-rc.2"`），
但桥接的版本号、守卫名单和两个校验脚本都还停在 0.2.0 的口径。DSH 0.2.1 改了两件与桥接**直接相关**的事：

| 0.2.1 变更 | 对桥接的影响 |
| --- | --- |
| **提示词变量表移除 `cwd`**（agent loop 只注册 `provider` / `model`） | 两个 preset 若还写 `{{cwd}}`，**每个回合**在装配阶段直接 error |
| **`dsh-base` 默认挂 `working-directory` + `tool-working-directory`** | 全局层多出 `working_directory`，QQ 仿真会话会继承它 |

第一件本机已经规避（persona 的 suffix 写死成文本，没写 `{{cwd}}`），**但测试断言是反的**；
第二件是本版补上的。

## 3. 修掉两处方向写反的断言（本版真正的隐患）

### 现象

`scripts/verify-dsh-021-adaptation.mjs`（原 `verify-dsh-020-adaptation.mjs`）和
`scripts/verify-persona-config.mjs` 里都有这一行：

```js
check(`preset ${p}: 保留 {{model}} / {{cwd}} 变量`,
  /\{\{model\}\}/.test(row.config.prefix) && /\{\{cwd\}\}/.test(row.config.suffix ?? ''));
```

它要求 persona 的 suffix **必须**含 `{{cwd}}`。

### 为什么这是反的

- DSH 0.2.1 的 `dsh-agent-loop` 只注册两个变量：
  `ctx.systemPrompt.variable("provider", ...)`、`ctx.systemPrompt.variable("model", ...)`。
  本机从 `app.asar` 里扫 `systemPrompt.variable(` 实测只有 **provider / model / response_language**。
- `dsh-system-prompt` 的 `interpolate()` 对未知变量是 **fail loud**：直接
  `throw new Error('unknown prompt variable "{{cwd}}" in section "deployment:persona-suffix"')`，
  **不是**渲染成空串。
- 于是带 `{{cwd}}` 的 preset，`turn/start` 之后立刻 `turn/end reason={kind:error}`，
  没有 `assistant/message`、没有 `tool/call` —— **模型一次都不跑**。
  QQ 侧的现象就是「发消息完全没反应」。
- 旧断言的方向：**能跑的状态判红，炸掉的状态判绿。**

### 改法

改成「**只允许** DSH 已注册的提示词变量」的双向对账：

```js
const REGISTERED_PROMPT_VARS = new Set(['provider', 'model', 'response_language']);
// 扫出 preset 里所有 {{var}}，与上面求差；有任何未注册变量就报红
```

两个脚本（`verify-dsh-021-adaptation.mjs` 与 `verify-persona-config.mjs`）同步改成这个口径，
与 `test-qq-preset-contract.mjs` 里已有的「不得出现 `{{cwd}}`」互为印证。

## 5. 对账工具修好了（`verify:adaptation` 首次全绿）

本机 DSH 是 **Electron 桌面版**，`@deepseek-ai/*` 全打在
`<安装目录>/resources/app.asar` 里，磁盘上没有可解析的 `node_modules`。
旧的对账脚本只认磁盘目录，在这类安装上**全废**：

| 症状 | 后果 |
| --- | --- |
| `verify:adaptation` / `verify-persona-config` 直接 `ERR_MODULE_NOT_FOUND` | 两个最重要的校验脚本一个都跑不了 |
| `scan-dsh-tool-names.mjs` 扫到 **0 个工具名** | 把 46 个**真实存在**的名字报成「假名」 |

「假名」这个方向特别危险 —— 它会逼人把真名字从守卫名单里删掉，等于**自己拆安全边界**。

### 修了什么

`scripts/dsh-modules.mjs`（新增约 200 行）：

- **asar 定位**：环境变量 → **从 DSH 自己的日志里抽 `resources/app.asar` 的绝对路径**
  （stack trace 里写着真实安装位置，比猜盘符稳）→ 常规布局兜底。**不硬编任何盘符**。
- **按需读文件**：`readDshFile` / `listDshDir` 磁盘与 asar 两种布局通用。
- **按需抽包再 import**：`importFromDsh` 把用到的包（含依赖闭包）抽到临时目录再 import ——
  Node 的 ESM loader 不认 asar 这个容器格式，直接 import 必失败。
  实测 `dsh-persona` 的闭包是 18 个包 / 704 个文件 / 约 0.5 秒。

`scripts/dsh-tool-names.mjs`：

- 包级**前缀拼装**：`dsh-ops` 把 `TOOL_PREFIX = 'ops_'` 写在 `lib/policy.js`，
  工具名在 `lib/capabilities/*.js`，注册出去是 `ops_read_files`、源码里只有 `read_files`。
  前缀常量与名字**不在同一个文件**，所以必须按包聚合。
- 工具顺序数组：`const fileOrder = ['read_files', ...]` 才是权威清单。
- 插件目录补上 `profiles/<p>/node_modules`（`dsh-ops` 实际装在这里，`plugins/` 下没有）。

### 踩过的三个坑（都已修，写下来免得重犯）

1. **`queued` 必须在入队时去重**，不能只靠出队后标记的 `copied`。
   依赖图有环时同一个包会被反复推回队列，每轮都对 180 MB 的 asar 重走一次
   `listDshDir`（那是遍历整棵子树）—— 表现为**进程挂死**，不是崩溃、没有异常。
2. **不能把整个 asar 读进内存**。180 MB 的 buffer 常驻后，抽 700+ 文件时峰值会压死进程，
   症状同样是**静默退出**（连 `process.on('exit')` 都不触发）。改成只缓存 JSON 文件树
   （约 5 MB），内容按 offset 单次读盘。
3. **原生包不进依赖闭包**。`node-addon-*` 这类包抽出来再 import 会让进程硬崩，
   而本用途（拿 `dsh-persona` 的 schema 做校验）完全不需要它们。

### 顺带修掉的一批「假红」

这些不是桥接坏了，是验证脚本的假设与本机实况不符：

| 旧断言 | 本机实况 | 改成 |
| --- | --- | --- |
| `web_search` 不得放行 | **故意**放行（不接受 URL、无 SSRF 面） | 只钉 `web_fetch` 不在 `SAFE_EXACT` |
| `DSH_BASE_URL` 默认 `:3080` | 桌面版在 `:19387` | 从 `desktop-preferences.json` 读端口 |
| 硬编码 `profiles/web` | 本机是 `profiles/desktop` | 自动挑存在的 profile |
| `model = deepseek-flash` | `deepseek-v4.1-flash` | 断言「deepseek 系」而非某个历史名 |
| `selectModel(deepseek-official, deepseek-flash)` | `provider=trae` | 从 `config.json` 读 provider/model |
| MCP 正好 3 个、全部在本仓库 | 5 个（多了 games/phone，phone 在别的目录） | 核心 3 个存在 + id 无重复；外部 MCP 跳过路径检查 |
| 活 DSH 段崩了会把整轮结果丢掉 | 端口没开时 `fetch failed` 直接退出 | 先探活，不可达就整段记为「跳过」 |

node scripts/test-preset-local-tools.mjs     → 7/7

## 8. 生效方式

- 守卫是 preset 行 import 的模块，运行中的 DSH 按 URL 缓存：**已经开着的会话仍用旧名单**，
  新建会话才用新名单。彻底生效（含既有会话）重启一次 DSH 即可。
- 本版**没有改 `bridge.js`**，所以桥接进程可以照常重启或继续跑；
  但因为守卫文件变了，要让新名单进 schema 仍需重启 DSH。
