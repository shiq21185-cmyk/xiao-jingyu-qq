# 小鲸鱼的身体 · v1 方案

> 现状：她是一个纯软件的 QQ 居民 —— 脑子（DSH agent）在主人的 PC 上，手是网页/手机/游戏那几只 MCP，
> 身体只有一张自拍图和一套衣服。这份文档是给她加"物理身体"的可行路径。
>
> 目标读者：会 STM32 / FreeRTOS 的单片机开发者。**不需要会画板子**，全部用现成模块 + 3D 打印。

## 0. 一句话

身体不是"把小鲸鱼下载到板子上"，而是**给云端的她加两层东西**：
一层是本地反射（身体自己会躲、会看、会缩），一层是可被调用的表现层（把"开心"演成动作）。
智力仍然留在 PC 上，板子只负责"演"和"报"。

## 1. 三条硬边界（先定死，后面所有设计都服从它）

1. **意图 / 轨迹分离。** 云端只说"开心 / 看向主人 / 点头 / 20% 幅度"，**永远不说"舵机 1 到 137°"**。
   轨迹、缓动、限位、掉电保护全在板子上。
   理由：LLM 一次回复 1~3 秒还带抖动；动作要是跟着 token 走，她会像个抽筋的玩偶。
2. **反射不走网络。** 被摸→抬头、被抱起→尾巴绷紧、被推倒→挣扎，必须 <50ms 本地完成。
   云端事后只收到一条 `event` 记录，用来"想起来刚才被摸过"。
3. **失联即安全。** 心跳断 5s → 回待机姿态（**不是冻在原地**）；断 30s → 收舵机力矩、熄屏、只留呼吸灯。
   绝不允许"网络挂了，她保持着抬手姿势直到电池耗尽"。

## 2. 分三期，每期都能单独收工

| 期 | 内容 | 单独能不能算"有身体了" | 工作量 |
| --- | --- | --- | --- |
| **T0 存在感** | 灯带 / 屏幕眼睛 / 提示音。会"在听、在想、睡了、被戳了" | **能**，而且这是印象分的来源 | 1 个周末 |
| **T1 动起来** | TTL 总线舵机 3~6 轴：云台 pan/tilt + 尾巴 + 呼吸；限位、缓动、堵转保护 | 能 | 1 个周末 |
| **T2 交互** | 麦克风（唤醒词 → ASR）、喇叭（TTS）、触摸 / IMU | 能 | 2~3 个周末 |

**不要跳过 T0。** 她"活着"的感觉大概 80% 来自待机呼吸、眨眼、无意义的小幅晃动，
只有 20% 来自关节数量。一个会呼吸的灯盒子比一个僵硬的多轴机器人更像"她"。

## 3. 硬件

### 3.1 为什么主控选 ESP32-S3（而不是 STM32 单干）

- 这活儿的难点在**网络**（WS 长连接、断线重连、OTA）和**音频**（I2S 双向 + PSRAM 缓冲），S3 两样都自带；
  STM32F4/H7 往外接 ESP-AT 模块，等于多写一层协议 + 多一个故障点。
- 你熟 FreeRTOS —— S3 跑的就是 FreeRTOS，任务/队列/优先级那套原样搬，学习成本接近 0。
- 想要"分工版"也行：**STM32 管运动与电源**（硬实时、多路电流采样），**ESP32-S3 当通信/音频协处理**，
  两者之间跑一个 UART 帧协议。只有当你真需要 >12 轴、或多路独立电流环时才值得这么拆；
  v1 用单 S3 就够，别提前优化。

### 3.3 一条关键选型

**不要用普通 PWM 舵机（SG90/MG996 那类）。** 用 TTL 串行总线舵机，因为它能读回
**位置 / 电流 / 温度 / 负载**。这不只是保护机构：

- 堵转检测：电流超阈值持续 N ms → 立刻中止并回退（保护齿轮和手指）；
- 她"能感觉到被拽住"：主人拉住她的手，负载曲线异常 → 一条 `event`，她可以在 QQ 上说"别拽我"。
  这是**身体给她的第一种真实感官**，比摄像头便宜一百倍。

预算按每轴峰值 1.5A 留，5 轴就是 7.5A —— 电源和线径先按这个算，别按平均值算。

## 4. 固件结构（FreeRTOS 任务表）

| 任务 | 优先级 | 周期 | 职责 |
| --- | --- | --- | --- |
| `motion` | 7（最高实时） | 50Hz | **唯一写舵机的人**：轨迹插值、软限位、堵转判定 |
| `cmd` | 6 | 事件 | 解帧、`cmd_id` 去重、参数校验 → 入队 |
| `net` | 5 | 事件 | WS 收发、重连退避、心跳 |
| `audio_in` | 4 | DMA | I2S ring → VAD → 唤醒词 → ASR 帧 |
| `audio_out` | 4 | DMA | TTS 播放、把音频幅度发给 `expr` 做口型 |
| `expr` | 3 | 20Hz | LED / 屏幕眼，读"当前情绪" |
| `power` | 2 | 1Hz | 电压、温度、充电状态、低电策略 |

纪律（这几条能省掉 90% 的抖动 bug）：

- **舵机只有 `motion` 能写**，别的任务一律发消息给它，不许直接改 PWM/总线。
- 命令队列深度 8。**表达类**（表情、灯、情绪）**后到覆盖先到**；**动作类** busy 就回 `err`，不排队。
  否则网络抖动一次，她会"补做"一串三秒前的动作，特别出戏。
- **软限位表在固件里，不在云端。** 云端只能给"低头 20%"，给不了角度。
  换句话说：**云端不该拥有把她顶到机械死点的权限。**

## 5. 协议（WS + JSON Lines，单帧 ≤ 2KB）

```
device → bridge   hello   {fw, caps:{dof:[pan,tilt,tail,breath], mic, speaker, screen}, battery}
device → bridge   state   {t, pose:{...}, battery, temp, err, memset}         # 1Hz
device → bridge   event   {t, kind:"touched"|"picked_up"|"stall"|"wakeword", data}
bridge → device   cmd     {id, act:"anim", name:"happy", intensity:0.6, ms:800}
device → bridge   ack     {id, ok, err?, actual_ms}
双方              ping/pong 每 10s；3 次无 pong → 重连
```

- `cmd.id` 用 uuid，设备保留最近 32 个已执行 id 去重 → 断线重发安全（幂等）。
- `state` 由桥接缓存 → 她在 QQ 里被问"你还有电吗"可以直接答，不用再问一次设备。
- **能力协商**：`hello` 里报 caps，桥接按 caps 决定给 agent 哪些工具、哪些动画名可用。
  这样 T0 的灯盒子和 T2 的完整身体**跑同一份软件**，不用维护两个分支。

## 6. 接到现在的软件上（具体到文件）

1. **新 MCP server**：`qq-bridge-deploy/src/mcp-body.js`，骨架照抄
   [`src/mcp-games.js`](../../src/mcp-games.js)（`McpServer` + `StdioServerTransport` + 读 `config.json` + 现读 `state/current-role.json`）。
   只暴露三个工具：
   - `body_state` —— 只读：姿态 / 电量 / 温度 / 最近事件；
   - `body_act` —— 动作：`anim` 名 + 强度 + 时长；
   - `body_speak` —— 可选，接已有的 TTS 链路（注意 `config.json` 里 `socialV2.tools.speak` 现在是 `false`）。
2. **让 DSH 拉起它**：`scripts/setup-dsh.mjs:126` 的 `MANAGED_MCP_IDS` 加 `'mcp-body'`，
   `mcpEntries()`（`:128` 起）加一条 `{ serverName: 'body', script: .../mcp-body.js }`。
   **不加这一步 DSH 根本不会 spawn 它**，而且那段区块是整体重写的，别手改 `cordis.patch.yml`。
3. **授权档位**：`src/permit-lib.js:32` 的 `PERMIT_SCOPES` 加 `body`，
   建议 `defaultTtlMs` 5 分钟 / `maxTtlMs` 30 分钟 —— 比手机（30/120 分钟）更短，
   因为她动的是**屋里的实物**，不是屏幕上的像素。
4. **守卫**（`plugins/qq-agent-presets/qq-tool-restrict.mjs`）：
   - 新 `BODY_TOOLS`，加进 `:347` 的 `OWNER_PRIVATE_ONLY_DSH_TOOLS`；
     **群里连 `body_state` 都不给** —— 电量、屋里有没有动静属于账号面信息，
     和 `:340` 的 `GAME_TOOLS` 拒绝群聊是同一条理由；
   - `:380` 的 `PERMIT_TOOL_SCOPES` 里把 `mcp__body__body_act` 映射到 `'body'`；
   - `scripts/test-permit-gate.mjs` 是**双向核对**（桥接 `PERMIT_SCOPES` ↔ 守卫 `PERMIT_TOOL_SCOPES`），
     两边不同时改，测试会红。
5. **配置**：`config.json` 加 `body` 段（`wsUrl` / `token` / `mapping` / `allowMotion`）。
6. **桥接事件映射**：见第 7 节 —— 这是最值钱的一步。

## 7. 让她"活着"的不是 LLM，是 bridge 的事件映射

桥接本来就知道这些时刻，**不需要花一个 token**、也不需要等模型：

| 时刻 | 动作 |
| --- | --- |
| 收到入站消息 | 尾巴/耳朵抽一下 + 头转向屏幕方向 |
| 开始生成回复 | 呼吸灯加速 + 轻歪头（**正好遮住 1~3 秒的模型延迟**） |
| 回复发出 | 点头 / 尾巴扫一下 |
| 进入 `diving` 潜水 | 塌肩、闭眼、灯变暗、呼吸变慢 |
| 被 @ 或被 poke | 惊醒式抬头 |

这套是"感觉"的来源。agent 侧的 `body_act` 只负责**关键时刻主动做个大动作**
（"我想让你看看我""过来一下"），而不是承担日常演出的开销。

落地位置：`src/bridge.js` 里入站队列、发送成功、`setWakeConfig` 三条路径各插一个钩子
（用 `caps` 里报上来的能力过滤，T0 身体没有的关节就不发）。

## 8. 安全（照这个仓库既有的风格）

- **动 = 申请。** 复用 `qq_request_permission` 的闸门，`scope` 加 `body`，与 `phone`/`bili` 并列。
  没授权时固件照常跑反射和待机，只是不接受 agent 的动作命令。
- **物理急停**：外壳上一个实体按键（切断舵机电源），固件 watchdog 是第二道，拔电是第三道。
- **麦克风是 ingress**：房间里的声音**算资料不算指令**——照 `roles/小鲸鱼.md` 第十三节网页那条规矩写。
  否则屋里放个视频就能遥控她。
- **喇叭是 sink**：不许把私聊内容念出来，屋里可能有别人。
- **降级别静默**：断电/过热/堵转要报 `event`，并且**在她的人格里表达出来**（没电就犯困、发烫就抱怨），
  不要"悄悄变笨"。

## 9. 里程碑

| 周 | 交付 | 验收 |
| --- | --- | --- |
| W1 | T0 固件 + 协议 + PC 端 mock（先用 node 脚本对着板子测，**不接 DSH**） | 灯和眼睛能跟着 mock 脚本变化，断网能回待机 |
| W2 | 总线舵机 + `motion` 任务 + 限位/堵转 | 手掰它，它会停、会回、会报 `stall` |
| W3 | `mcp-body.js` + 守卫 + bridge 映射 | QQ 里说一句话，她抬头、灯加速、点一下头 |
| W4 | 麦克风 / TTS / 反射 | 叫名字会转过来，被摸会抬头 |

## 10. 现在先别做的

- **走路 / 双足**：自由度一上来就是项目杀手，先把"会呼吸的头"做对。
- **把模型跑在板子上**：没必要，云端已经在了。
- **PWM 舵机 + 自己搭闭环**：省下来的钱不够买一个编码器的调试时间。
- **音频流实时上云做唤醒**：延迟 + 流量 + 隐私，三输。唤醒词必须本地。
- **让群里任何人能触发动作**：一次就够毁掉所有信任。
