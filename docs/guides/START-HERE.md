## 1. 这是什么项目

给小鲸鱼（一个跑在 PC 上、通过 QQ 说话的软件人格，仓库 `qq-bridge-deploy`）
加一个**物理身体**：ESP32-S3 + FreeRTOS + 总线舵机 + 屏幕眼睛 + 麦克风/喇叭。

**智力留在 PC 上**（DSH agent 负责推理、人格、记忆），
**板子只管两件事**：本地反射（被摸/被抱/被推倒，<50ms，不走网络）+ 表现层（把"开心"演成动作）。

主人背景：熟悉 STM32 / FreeRTOS / 嵌入式，**没做过 ESP32，不需要画 PCB**。

## 3. 已经定死的决定（不要再推翻）

1. **意图 / 轨迹分离**：云端只说 `"happy", intensity 0.6`，**永不说角度**。限位、缓动、掉电保护在固件里。
2. **反射不走网络**：<50ms 本地完成，云端事后只收到 `event`。
3. **失联即安全**：心跳断 5s 回待机，30s 卸力。绝不"保持姿态直到电池耗尽"。
4. **主控 ESP32-S3-WROOM-1-N16R8**（八线 PSRAM 必须 R8），不是 STM32 单干 —— 难点在网络和音频，不是算力。
5. **舵机必须 TTL 总线型（Feetech STS3215）**，要能读回电流/温度 —— 这是堵转保护和"被抓住"感觉的唯一来源。
6. **电源按 5A 设计**，靠固件"同时最多 2 轴加速"排班，不堆 12A 电源。
7. **急停是硬件断舵机 VM**（常闭按钮 + P-MOS），不依赖固件。
8. **只有 `motion` 任务能写舵机**，别的任务发队列消息。

## 4. 最容易踩的坑（血泪清单）

- **舵机 ID 出厂全是 1**，五个一起接 = 地址冲突。必须一个一个改（BODY-BUILD §5.2）。
- **STS3215 有 6V/7.4V/12V 多个版本在流通**，电源要按手上那批的铭牌买（§2.1）。
- **R8 必然丢 GPIO33–37**；禁区还有 26–32(Flash)、19/20(USB)、43/44(UART)、0/3/45/46(strapping)。
- **舵机和 MCU 共地但绝不共电源路径**，否则舵机一动 ESP32 就复位。
- **`scripts/test-permit-gate.mjs:92` 硬编码 `['bili','phone']`**，加 `body` scope 会判红，要同步改。
- **`scripts/setup-dsh.mjs:126` 的 `MANAGED_MCP_IDS` 不加 `mcp-body`，DSH 根本不会 spawn 它**；且那段 cordis 区块是整体重写的，别手改内部。

## 5. PC 侧要改的地方（仓库 `qq-bridge-deploy`，已核对行号）

| 改什么 | 文件:行 |

| 配置 | `config.json` 加 `body` 段，`enabled` 默认 false |
| **事件映射（最值钱）** | `src/bridge.js`：入站热路径（`:13643` 一带）、`deliverPromptNow()`（`:11537`）、`sendChain` then（`:9424`/`:9616`）、`setWakeConfig` 分支 |

事件映射的作用：收到消息抽尾巴、**开始生成时呼吸加速+歪头（盖住 1~3 秒模型延迟）**、发完点头、潜水时塌肩闭眼。
**不花一个 token、不等模型。** 这套才是"活着"的来源；agent 侧 `body_act` 只负责关键时刻主动做大动作。

## 6. 施工顺序（别跳）

```
阶段0  PC 端 mock（不碰板子）：node 脚本假扮设备，先把 mcp-body.js / 守卫 / bridge 钩子跑通
阶段1  板子点亮：hello world + PSRAM 认到 8MB
阶段2  总线通：sync write 单舵机转 0/30/-30
阶段3  五轴动：50Hz + 软限位 + 加速度限制
阶段4  堵转保护：拦住 200ms 卸力 + 上报 event
阶段5  接 WS：拔网线 5s 回待机、30s 卸力
阶段6  接 DSH：QQ 说一句，她抬头
阶段7  灯 + 眼睛 + 呼吸（决定"像不像活的"）
阶段8  麦克风 / TTS / 触摸 / IMU
```

按天排（周末党）：D1 环境、D2 屏+灯、D3 改舵机 ID+量限位、D4 bus 层、D5 控制环、D6 堵转+电源策略、
D7 WS、D8 接 DSH、D9 动画调参、D10 装配、D11+ 交互。**两周出"她动了"。**
